## Implementation

`PrismaTournamentAcknowledgementGuard` runs in a serializable Prisma transaction immediately before `startRunning`. It pins the tournament's server-side `activeConfigVersionId`, rejects a stale/missing or malformed published regulation, and calls the existing `TournamentAcknowledgementService.assertAcknowledged` for every eligible account enrollment. No second ACK model or client-supplied authority was introduced. The guard is installed only for real `PrismaDatabase` composition; existing in-memory L10 fixtures remain deterministic.

The admission-check route now derives principal identity and roles from the authenticated server context and uses request data only for the requested operation and scope.
