## Findings and handoff

### D12-F01 — P10 foreign roster list returns foreign enrollment data

The real `TOURNAMENT_ADMIN` A session requested `/admin/tournaments/d12a-tournament-b1/roster`. The route authorizes only the broad role and calls `RosterService.listEnrollments(tournamentId)` without actor scope. The response returned the B1 enrollment sentinel. This is a P1 direct-ID authorization/data-disclosure finding owned by the roster/account owner, with shared authorization review if the fix changes a common contract.

The corresponding foreign commit was denied and its enrollment, command-ledger, and audit counts were unchanged.

### D12-F02 — P10 administrative shell renders after a normal-user API denial

The browser test logged in as a normal persisted account, navigated directly to the P10 roster route, and observed a 403 from the roster API. The page nevertheless rendered the P10 administrative shell. The runner did not observe foreign roster data in this case, so this is P2 UI/authorization-boundary evidence rather than a data-disclosure escalation. Route/UI guard ownership is Sơn; API coordination remains Đức.

### D11-F09 — reconfirmed in D12

The audit API returned the synthetic token-like audit reason written through the existing contract update path. This is the same D11 finding, not a new finding number. `audit.port.ts` was not modified. Remediation belongs in the shared audit boundary and should be handed to D13/Long.
