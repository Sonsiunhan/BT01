## Implemented behavior

- `RosterService.commitRosterImport` now treats the durable `CommandLedgerEntry` as the recovery authority after a transaction/response ambiguity or a concurrent unique-key loser. A matching digest replays the committed response; a different digest returns `409 IDEMPOTENCY_KEY_REUSED`; a different key racing on the database `person_key` fence returns canonical `DUPLICATE_PERSON_KEY`.
- `ActivationService.claimActivation` re-reads the durable claim ledger after a concurrent transaction loses the username/claim uniqueness race. The loser safely replays the winner without a second user, enrollment link, credential write or audit row.
- `TournamentStaffService` fences invitation acceptance/decline with a conditional `INVITED` row update. One request records the terminal transition; a concurrent request replays the terminal decision, and opposite/state/expiry races remain conflicts.
- Recovery consumption keeps the existing conditional token claim and shared transaction for credential/session/audit writes. D09-B adds a true two-caller race harness and verifies only one completion audit and credential write.
- Audit assertions cover rollback and race paths. Raw token, password, password hash, token hash, source and private input are not emitted into the tested public/audit evidence.

No Prisma schema or migration change was needed.
