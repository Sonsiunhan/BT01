## Verified findings

The finding sequence continues after D11-A's F01/F02 and the previously recorded
D11-F03 through D11-F05.

### D11-F06 - P1 - create transport failure reports fake success

Reproduction: abort `POST /api/tournaments/drafts` in the real browser. The page
navigates to a generated `/admin/tournaments/draft-*` URL, shows revision `r1`, and
does not render an error. The API client catches a non-HTTP fetch failure and
returns a locally generated mock DTO.

Impact: the user is told that a draft exists although no authoritative create
response was received. This violates T079 recovery and the server-authority rule.

### D11-F07 - P1 - hidden BOT deadline survives a mode cycle

Reproduction: enter a BOT deadline, switch `BOT_VS_BOT` to `HUMAN_ONLINE`, switch
back, and reopen the schedule step. The previous deadline is restored. The field
is hidden while HUMAN is selected, but the form state is not reset when the mode
changes.

Impact: a value that should be not-applicable can become active again without a
new deliberate entry, contrary to T071. Contract normalization protects the
HUMAN payload at save time but does not remove the stale UI state.

### D11-F08 - P1 - UNLISTED is emitted as INTERNAL_UNIT

Reproduction: select the visible `UNLISTED` option and capture the outgoing create
payload. The payload contains `audienceScope: INTERNAL_UNIT` and the default
internal unit code rather than a distinct invited/unlisted contract scope.

Impact: the UI's BA/SA F07 choice is not represented by the outgoing contract.
The form and DTO mapping only distinguish PUBLIC from the non-PUBLIC branch,
while the contract exposes `INVITED_LIST` as a distinct audience scope.
