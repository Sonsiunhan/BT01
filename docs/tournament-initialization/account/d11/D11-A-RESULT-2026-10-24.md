## F01 — authoritative tournament/audit API integration

Verdict: VERIFIED FINDING

`apps/web/src/features/admin/tournaments/tournamentApi.ts` defaults `TournamentApiClient` to `useRealApi = false`, and the router/page defaults use `defaultTournamentApi`. P01 list and P14 audit therefore return client fixture data without calling the authoritative API. P03 detail/readiness paths do issue real requests, but their fallback/error behavior is inconsistent and does not establish a complete authoritative integration.

Executable P01/P14 browser evidence used real authenticated accounts and observed no `/api/tournaments` or `/api/admin/audit-logs` request while fixture content rendered. This confirms the finding rather than treating S10's mocked route responses as proof of API integration.

## F02 — authenticated direct-route authorization

Verdict: VERIFIED FINDING

`apps/web/src/features/admin/shell/AdminCapabilityGuard.tsx` declares `requiredCapability` but does not evaluate it. The guard only distinguishes loading and unauthenticated states, then renders children for every authenticated user. `apps/web/src/layouts/AdminLayout.tsx` also mounts the guard without a capability requirement.

The executable browser path registered four real accounts and directly opened the routes. PLAYER, REFEREE, scoped TOURNAMENT_ADMIN, and SYSTEM_ADMIN all reached the Admin shell and protected page components. This confirms that client route admission is broader than the intended role/capability matrix. Server-side API checks still reject unauthorized authoritative operations; that does not fix the UI authorization finding.

## Online admission and manipulation

The real server admission request used an intentionally manipulated payload role of `PLAYER` while authenticated as SYSTEM_ADMIN. The route overwrote payload identity and roles from the server actor. Result: HTTP 200 with `decision.allowed=false` and `decision.reasonCode=ADMIN_CANNOT_PLAY_ONLINE`.

This verifies the T005 server-side admin-play restriction and that client payload role values do not grant online player authority.
